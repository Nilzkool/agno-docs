title: Environment variables
---

Environment variables can be added to resources using the `env_vars` parameter or the `env_file` parameter pointing to a `yaml` file. Here are some examples of how environment variables are configured in a typical workspace:

```python dev_resources.py
dev_fastapi = FastApi(
    ...
    env_vars={
        "RUNTIME_ENV": "dev",
        # Get the OpenAI API key from the local environment
        "OPENAI_API_KEY": getenv("OPENAI_API_KEY"),
        # Database configuration
        "DB_HOST": dev_db.get_db_host(),
        "DB_PORT": dev_db.get_db_port(),
        "DB_USER": dev_db.get_db_user(),
        "DB_PASS": dev_db.get_db_password(),
        "DB_DATABASE": dev_db.get_db_database(),
        # Wait for database to be available before starting the application
        "WAIT_FOR_DB": ws_settings.dev_db_enabled,
        # Migrate database on startup using alembic
        # "MIGRATE_DB": ws_settings.prd_db_enabled,
    },
    ...
)
```

```python prd_resources.py
prd_fastapi = FastApi(
    ...
    env_vars={
        "RUNTIME_ENV": "prd",
        # Get the OpenAI API key from the local environment
        "OPENAI_API_KEY": getenv("OPENAI_API_KEY"),
        # Database configuration
        "DB_HOST": AwsReference(prd_db.get_db_endpoint),
        "DB_PORT": AwsReference(prd_db.get_db_port),
        "DB_USER": AwsReference(prd_db.get_master_username),
        "DB_PASS": AwsReference(prd_db.get_master_user_password),
        "DB_DATABASE": AwsReference(prd_db.get_db_name),
        # Wait for database to be available before starting the application
        "WAIT_FOR_DB": ws_settings.prd_db_enabled,
        # Migrate database on startup using alembic
        # "MIGRATE_DB": ws_settings.prd_db_enabled,
    },
    ...
)
```

### AWS Environment Variables in Docker Applications

Docker applications can now recognize and utilize AWS environment variables for local development. This is managed through the `set_aws_env_vars` function in `agno.docker.app.base.DockerApp`.

Common AWS environment variables that can be set for your Docker apps include:

- `AWS_REGION`
- `AWS_DEFAULT_REGION`
- `AWS_PROFILE`

### Managing Database Credentials with AWS Secrets Manager

For enhanced security, DB cluster master user passwords can now be managed directly with AWS Secrets Manager. This is configured via the `manage_master_user_password` and `master_user_secret_kms_key_id` parameters in the `agno.aws.resource.rds.db_cluster.DbCluster` resource.

Example for an RDS DB Cluster:

```python
from agno.aws.resource.rds.db_cluster import DbCluster

dev_db = DbCluster(
    name="my-dev-db",
    engine="aurora-postgresql",
    engine_version="15.5",
    # ... other configurations
    manage_master_user_password=True,
    # Optional: specify a KMS key to encrypt the secret
    master_user_secret_kms_key_id="arn:aws:kms:us-east-1:123456789012:key/your-kms-key-id",
)
```

The apps in your templates are already configured to read environment variables.
