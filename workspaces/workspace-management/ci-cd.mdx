# CI/CD

Agno projects come pre-configured with GitHub Actions for CI/CD. Out of the box we have:

1. Test and validate on every Pull Request
2. Publish the Python package on every Release

## Test and validate on every PR

Whenever a PR is opened against the `main` branch, the `test.yml` workflow runs to ensure:

- The code is formatted using Ruff
- All unit tests pass
- There are no type-checking or linting errors

Checkout the `.github/workflows/test.yml` file for more details.

<img src="/images/test-cicd.png" alt="test-cicd" />

## Publish Python package on releases

When you create a GitHub Release (e.g. `v1.0.0`), the `release.yml` workflow builds and publishes the Python package to PyPI.

Check the `.github/workflows/release.yml` file to see how the package is built (`python3 -m build`) and uploaded via Twine.

<Note>
Make sure that your project’s version metadata and package name are correct in `setup.cfg` or `pyproject.toml` before creating a release.
</Note>

<CodeGroup>
```bash Mac
# Create a new GitHub Release
gh release create v1.0.0 --title "v1.0.0" -n ""
```

```bash Windows
# Create a new GitHub Release
gh release create v1.0.0 --title "v1.0.0" -n ""
```
</CodeGroup>

<img src="/images/github-actions-release.png" alt="github-actions-release" />

<Note>
You can also trigger the release workflow manually with:

```bash
gh workflow run release.yml
```
</Note>
