## Test and Validate on every PR

Whenever a PR is opened against the `main` branch, a validate script runs that ensures

1. The changes are formatted using ruff
2. All unit-tests pass
3. The changes don't have any typing or linting errors.

Checkout the `.github/workflows/test.yml` file for more information.

## Build Docker Images on Release

If you're using [Docker Hub](https://hub.docker.com/) for images, you can build and push the images through a GitHub Release. This workflow is defined in the `.github/workflows/release.yml` file.

1. Create a [Docker Access Token](https://hub.docker.com/settings/security) for GitHub Actions.

<img src="/images/docker-access-token.png" alt="docker-access-token" />

2. Create secret variables `DOCKERHUB_REPO`, `DOCKERHUB_TOKEN` and `DOCKERHUB_USERNAME` in your GitHub repo. These variables are used by the release workflow.

<img src="/images/github-actions-docker-secrets.png" alt="github-actions-docker-secrets" />

3. Run the release by creating a new GitHub Release:

<Note>

Confirm the image name in the `.github/workflows/release.yml` file before running.

</Note>

<CodeGroup>

```bash Mac
gh release create v0.1.0 --title "v0.1.0" -n ""
```

```bash Windows
gh release create v0.1.0 --title "v0.1.0" -n ""
```

</CodeGroup>

<img src="/images/github-actions-build-docker.png" alt="github-actions-build-docker" />

<Note>

You can also run the workflow using `gh workflow run release.yml`.

</Note>

## Build ECR Images on Release

If you're using Amazon ECR for images, you can build and push the images through the same release workflow in `.github/workflows/release.yml`. It uses OpenID Connect (OIDC) to authenticate without long-lived IAM keys.

Follow the [AWS OIDC setup guide](https://aws.amazon.com/blogs/security/use-iam-roles-to-connect-github-actions-to-actions-in-aws/) to create an IAM role for GitHub Actions.

<img src="/images/github-oidc-provider.png" alt="github-oidc-provider" />

After you assign the role and policies, set these environment variables in your release workflow or repository secrets:

```yaml
# .github/workflows/release.yml
env:
  ECR_REPO: <YOUR_ECR_REPO>
  AWS_ROLE: <GITHUB_ACTIONS_ROLE_ARN>
  AWS_REGION: us-east-1
```

Then publish a new GitHub Release as above. The `release.yml` will build and push both Docker Hub and ECR images in one go.

<img src="/images/github-actions-build-ecr.png" alt="github-actions-build-ecr" />
