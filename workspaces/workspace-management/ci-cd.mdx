## Test and Validate on every PR

Whenever a PR is opened against the `main` branch, a validation script runs that ensures:

1. The changes are formatted using `ruff`
2. All unit-tests pass
3. The changes don’t have any typing or linting errors

Checkout the `.github/workflows/test.yml` file for more information.

## Build Docker Images with GitHub Releases

If you’re using [Docker Hub](https://hub.docker.com/) for images, you can build and push the images through a GitHub Release. This action is defined in the `.github/workflows/docker-images.yml` file.

1. Create a [Docker Access Token](https://hub.docker.com/settings/security) for GitHub Actions

<img src="/images/github-actions-docker-secrets.png" alt="github-actions-docker-secrets" />

2. Add the following secrets to your repo:
   - `DOCKERHUB_USERNAME`
   - `DOCKERHUB_TOKEN`
   - `DOCKERHUB_REPO`

3. Create a GitHub Release to trigger the workflow:

   ```bash
   gh release create v0.1.0 --title "v0.1.0" -n ""
   ```

## Build ECR Images with GitHub Releases

If you’re using AWS ECR for images, you can build and push the images through a GitHub Release. This action is defined in the `.github/workflows/ecr-images.yml` file and uses OpenID Connect (OIDC) for authentication without IAM keys.

Follow the [AWS OIDC setup guide](https://aws.amazon.com/blogs/security/use-iam-roles-to-connect-github-actions-to-actions-in-amazon-web-services/) to create an OIDC identity provider and IAM role. Then:

```yaml
# .github/workflows/ecr-images.yml
name: Build ECR Images

on:
  release:
    types: [published]

permissions:
  id-token: write  # required for OIDC
  contents: read   # required for checkout

env:
  AWS_ROLE: arn:aws:iam::123456789012:role/GitHubActionsRole
  AWS_REGION: us-east-1
  ECR_REPO: 123456789012.dkr.ecr.us-east-1.amazonaws.com/your-repo
```

Create a GitHub Release to run this workflow:

```bash
gh release create v0.2.0 --title "v0.2.0" -n ""
```
